2-test run of the bootstrap-disabled authorization fallbacks. Real Google Chrome
(`PLAYWRIGHT_CHANNEL=chrome`), one worker, no retries.

`127.0.0.1`. The server used the seeded `judge-v2` warehouses, the operator
service key and the supervisor token produced by `scripts/judge_setup.sh`.

- unauthenticated reads and privileged mutations are 401; a query-string key is
  not accepted;
- the service principal cannot drain, run jobs, write packs, delete DSR data,
  configure connectors, or add case notes;
- SSRF targets are rejected with 400 when an authorized admin session is
  available, and the service key is denied with 403;
- the OpenAPI GET sweep returns no 5xx; optional Google OIDC fails closed with
  503 when unconfigured; the audit export returns a SHA-256 manifest and

  the settings key handling behaves;
- the judge workflow performs operator-key sign-in, displays the recorded live
  proof, exchanges the supervisor token into an HttpOnly cookie, takes over and
  releases the contact, with no page exceptions.

## Bootstrap-disabled fallbacks

The admin-only branches above are environment-gated by
`FRONTLINE_BOOTSTRAP_ADMIN`. On a server without it, the same specs verify the
denial path and annotate that the admin half was not available:

```bash
cd dashboard
BASE_URL=http://127.0.0.1:8132 E2E_API_KEY=<operator key> \
PLAYWRIGHT_CHANNEL=chrome \
npx playwright test e2e/api.aggressive.spec.js e2e/api.deep-sweep.spec.js \
  -g "connector SSRF|case note author" --reporter=list
```

Result: **2 passed**. Log:
[`bootstrap_disabled_2026-10-28.txt`](bootstrap_disabled_2026-10-28.txt).

## Spec updates made during verification

Three old assertions contradicted the current hardened product and were updated
to test the intended behavior, not relaxed:

- `/health` is sanitized on an auth-required server and must not claim a SOC 2
  baseline; the old spec expected `security.soc2_engineering_baseline === true`.
- `PUT /connectors/config` and `POST /cases/{id}/notes` require admin-only
  `ops:write` / `case:write`; the old specs used the service key and expected
  200. The tests now verify the service-key 403 and use a bootstrap admin
  session for the SSRF/author checks when one is available.
- `GET /cases` intentionally excludes `channel='simulated'` unless
  `include_simulated=true`; the case-note and drawer tests now opt in, and the
  drawer test no longer treats the empty-state row as a case row.
